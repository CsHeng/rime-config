# 需求

本文记录 rime-config-go 要解决的问题、用户约束和验收条件。实现结构与关键取舍见 [架构](architecture.md)，使用方法与当前验证状态见 [README](../README.md)。

## 目标

- R1 提供原生 Windows amd64、macOS arm64 可执行程序（macOS amd64 顺带构建），完成万象资源更新、本地配置分层、多个 Rime 前端分发、部署和用户词库同步。日常运行不需要 Go、PowerShell 7、Git Bash、yq、jq、rsync、curl 或 unzip。
- R2 用户词库同步是必需能力。Windows 与 macOS 的 Rime 使用同一账号、同一逻辑目录的 OneDrive 同步树；macOS 另用 Unison 双向同步 OneDrive 与 iCloud 两个同步目录，供 iOS Rime（Hamster3）使用。
- R3 支持多个前端同时启用：Squirrel、Weasel、Hamster3，保留 Hamster 作为可选配置。iOS 是 macOS 向 iCloud 目录分发文件的目标，本程序不在 iOS 上运行。
- R4 本仓库独立拥有代码、配置、静态资源、测试、缓存、构建和文档。不引用其他工具仓库的模块、脚本、模板路径、缓存或产物，不使用 go.work、跨仓库 replace、子模块、符号链接、共享生成器，也不在运行时下载或调用另一个更新器。
- R5 本工具可以与其他工具共存并独立安装、更新、停用，不负责迁移、调用或卸载其他工具。真实试用时各工具顺序运行，不能并发写同一 Rime 目录，也不能对同一对目录并发运行 Unison。

## 用户约束

- U1 电脑与手机都只用全拼；九键（t9）相关配置不维护。
- U2 程序面向用户的输出（日志、错误、计划、帮助）用英文；Rime YAML 注释和人读文档用中文。
- U3 用户置顶短语可能含个人信息：它不进 git、不进交付包，但用户能在仓库里保留和编辑它。
- U4 运行时状态可随时丢弃，只放在项目自己的工作目录（默认 `build/`）中，不写入用户配置目录或 `~/Library`；内部路径不通过环境变量、`mise.toml` 或新增配置项暴露。
- U5 不使用“桥接/bridge”的说法，统一称 Unison 同步或云同步。
- U6 Hamster 皮肤源码放在本仓库 `resources/`，构建出的 `*.cskin` 不进 git。

## 用户数据边界

- R6 `user.yaml`、`installation.yaml`、任意层级 `*.userdb` 与其快照、目标 `build/` 永不写入；现有 `installation_id` 与 `sync_dir` 由用户管理，工具不改写。
- R7 默认只复制不删除；只有显式 `--delete` 才清理目标中不再分发且不受保护的文件，预览必须列出这些删除。
- R8 写入前完成全部预检：目标、命令、层目录和路径重叠、符号链接逃逸等问题在下载或写入之前失败。
- R9 `--dry-run` 只可更新工具自己的可重建缓存，不写目标、不创建用户短语、不调用 Rime 或 Unison。

## 完成与失败

- R10 进程退出、已提交请求或固定等待都不等于部署或同步完成；每一步要有可观察的完成证据，拿不到证据时报告未完成并以非零退出，不执行依赖它的后续步骤。
- R11 `--cloud-sync` 的顺序是 Unison 同步 → Rime 同步完成 → 再次 Unison 同步；Rime 同步未确认完成时不执行第二次。Windows 上显式 `--cloud-sync` 在任何副作用之前报错。
- R12 OneDrive/iCloud 客户端负责远端传输。本工具不登录账号、不调用云 API、不承诺远端立即一致；本地完成不能替代另一台设备上的候选词验证。

## 验收

离线测试、交叉编译和文件存在检查不能代替真实设备验收。真实用户数据操作前先备份将被改动的 installation 与快照，并确认云客户端已把所需文件下载到本地。

- V1 在真实 Windows 上运行交付包：更新与部署后自定义短语能置顶，原有自造词仍可用；`--sync-only` 不下载资源且实际导出本机快照。
- V2 用唯一测试词验证 Windows → OneDrive → Mac 以及反向导入，确认两端指向同一逻辑 OneDrive 目录，并等待客户端同步完成，不用固定等待来推测成功。
- V3 验证 iOS → iCloud → Mac（Unison → Rime → Unison）→ OneDrive → Windows 以及反向流程；手机端自行同步，部署后 userdb 不丢失。
- V4 用户比较安装与升级成本、Mac 日常流程、同步可靠性和改配置后的反馈速度，再决定保留或停用；不设必须胜出的指标。

失败时优先修复对应步骤：不重置 installation、不清空云目录、不导入旧数据库覆盖新数据。停用只需不再运行本工具，用户数据保持原样。
